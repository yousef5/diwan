# Diwan (ديوان) 1.0 — design

*2026-10-22. Status: approved by Joe; implementation plan in `docs/superpowers/plans/2026-10-22-diwan-1.0.md`.*

Diwan is a multi-account WhatsApp desktop client for Linux. It replaces Joe's earlier app
Nexus (`/mnt/joe-data/Coding/newWhatApp`, package `multiwhatsapp`). It is a new project, not a
fork. It keeps only the parts of Nexus that were proven in daily use: the `whatsapp:` deep-link
handling and the hung-page watchdog. The bar is "pro tool": calm Graphite look, keyboard-first,
no surprises, and no way to lose an account.

## 1. Goals and non-goals

**1.0 goals**

1. Every account runs WhatsApp Web in its own isolated session. Switching is instant.
2. The app behaves like a native desktop app. Links open in the browser. Right-click works, with
   Arabic + English spellcheck. Downloads save without a dialog. Notifications name the account,
   and clicking one opens that account *and that chat*. Unread counts show on the tray icon and
   the window title.
3. Account data cannot be lost. A corrupt or half-written config never turns into an empty
   account list.
4. One-time **Import from Nexus** moves Joe's logged-in accounts across without a new QR scan.
5. Graphite UI: quiet greys, one blue accent, Inter, rounded 8–12 px, per-account colour.
6. Unit tests for every module that holds logic, and a smoke test that launches the app.

**Later (separate specs)**

- **1.1 Pro features:** unified inbox, Ctrl+K command palette, quick-reply templates (inserted into
  the composer; the user presses Enter), app lock (PIN) + privacy blur, per-account quiet hours,
  hibernating idle accounts.
- **1.2 Local AI:** translate a message and suggest replies with Ollama on this PC. Nothing leaves
  the machine.

**Never**

- Sending anything automatically (scheduled messages, auto-replies, bulk sends). WhatsApp treats
  that as automation and can ban the number.
- "WhatsApp" or "Whats" in the product name or icon (Meta trademark).

## 2. Engine decision: Electron, not Tauri

Measured on joe-cachyos on 2026-10-22 with WebKitGTK 4.1 2.54.1, the engine Tauri 2 uses on
Linux (spike script: `docs/spikes/webkitgtk-whatsapp.py`):

| Check | WebKitGTK |
|---|---|
| web.whatsapp.com loads, QR shown, no "unsupported browser" | yes |
| Renders correctly on the RX 580 under Wayland | yes |
| MediaRecorder opus/ogg, H.264 + opus playback (voice notes, video) | yes |
| `RTCPeerConnection` (calls) | **no** |
| Custom user agent applied | **no** |
| Memory, QR page only | 766 MB RSS (Nexus with 2 logged-in accounts: ~1 GB PSS in total) |

Tauri would not save memory: the WhatsApp page dominates, whatever the shell. It would lose
calls, and it would run a different engine per OS (WebKitGTK / WebView2 / WKWebView), which means
three engines to test. WhatsApp ships web changes weekly and tests Chrome first, so Chromium is
the engine least likely to break. This is also why Ferdium, Rambox and Beeper are Electron apps.

**Decision:** Electron (latest stable, 41.x at the time of writing).

## 3. Architecture

```
┌──────────────────────── main process (Node) ────────────────────────┐
│ store/        diwan.json: validated, atomic, backed up                │
│ accounts/     registry: account ⇄ partition ⇄ webContents             │
│ guests/       hardening, link policy, context menu, downloads,        │
│               zoom, watchdog, input shortcuts                         │
│ notify/       native notifications, click → account + chat            │
│ unread/       per-account counts → tray badge, window title, urgency  │
│ importer/     Nexus → Diwan, copy-on-write                            │
│ ipc/          typed, validated channels (shell ⇄ main, guest → main)  │
└──────▲──────────────────────────────────────────────▲─────────────────┘
       │ shell IPC (contextBridge)                     │ guest IPC (ipcRenderer.send)
┌──────┴───────── shell renderer (React) ───────┐ ┌────┴── guest preload (one per account) ──┐
│ account rail, status overlays, settings,       │ │ runs inside web.whatsapp.com, isolated    │
│ add-account + import dialogs, tray badge PNGs  │ │ world: title → unread, Notification       │
│ <webview partition="persist:acc-<id>"> × N     │ │ bridge, avatar, connection state          │
└────────────────────────────────────────────────┘ └───────────────────────────────────────────┘
```

**Rule:** all logic lives in main or in the guest preload. The shell renderer only draws state it
receives and sends user intents. The shell never runs `executeJavaScript` against a guest, and
nothing polls on a timer. The guest preload pushes events when something changes.

### 3.1 Why `<webview>` and not `WebContentsView`

Electron recommends `WebContentsView` for new apps. Diwan still uses the `<webview>` tag, because
the shell must draw *over and around* the WhatsApp page: status overlays now, and the 1.1 lock
screen, privacy blur (`filter: blur()` on the element), command palette and inbox. A native view
cannot be covered by DOM, and faking that with screenshots is fragile. `<webview>` is OOPIF-based,
maintained, and is what Ferdium and Rambox ship. The cost is managed by doing all security
hardening in main (`will-attach-webview`, below).

### 3.2 Process and module layout

```
src/
  main/
    index.ts            app lifecycle, single instance, window, tray
    store/              schema.ts (zod), store.ts (load/save/recover), migrate.ts
    accounts/           registry.ts
    guests/             harden.ts, link-policy.ts, context-menu.ts, downloads.ts, zoom.ts,
                        watchdog.ts, shortcuts.ts
    notify/             notify.ts
    unread/             unread.ts, tray.ts
    importer/           nexus.ts (plan: pure; apply: fs)
    ipc/                channels.ts (shared types + zod), shell.ts, guest.ts
  preload/
    shell.ts            contextBridge API for the React shell
    guest.ts            runs in every web.whatsapp.com page
  renderer/             React shell (components/, state/, styles/)
  shared/               types and constants used by more than one process
tests/                  vitest unit tests, fixtures/, e2e/ (Playwright _electron smoke)
```

Each module exports a small interface and has no knowledge of the UI. `link-policy`, `schema`,
`migrate`, the importer's `plan`, the unread parser and the shortcut map are pure functions, so
they are unit-tested without Electron.

## 4. Components

### 4.1 Store (`store/`)

- File: `~/.config/Diwan/diwan.json` (Electron `userData` for productName "Diwan").
- Shape (`schemaVersion: 1`): `accounts[]` {id (uuid), name, color, order, zoom, muted,
  avatarFile?, createdAt}, `settings` {closeToTray, startHidden, notifications {enabled, sound,
  showPreview, markUrgent}, showWindowControls, window {bounds, maximized}}.
- Validated with zod on every load. Unknown fields are dropped, and missing ones get defaults.
- **Write path:** a single writer in main, debounced 300 ms. Each save writes `diwan.json.tmp`,
  fsyncs it and renames it over `diwan.json`. Before replacing, the previous good file is kept as
  `diwan.json.bak`.
- **Read path:** if `diwan.json` is missing → defaults (first run). If it is present but invalid
  → load `.bak`. If both are bad → **recovery mode**. In recovery mode the store is read-only:
  nothing is ever saved over the broken file, the shell shows a banner ("Settings file is damaged:
  Open folder / Start fresh"), and the partitions on disk are untouched.
- `migrate.ts` maps older `schemaVersion`s forward. Version 1 has no migrations, but the hook
  exists and is tested.
- Removing an account deletes its partition directory *after* the webview is destroyed. This
  avoids Nexus's 9 orphan partitions (~530 MB).

### 4.2 Account registry (`accounts/`)

- Partition per account: `persist:acc-<uuid>`.
- On `did-attach-webview`, main maps the guest `webContents` to its account by comparing
  `wc.session` with `session.fromPartition(...)` for each account. Every guest IPC message is
  resolved through this map. A message from an unknown sender is dropped.
- Session setup per partition, done once: permission handlers (allow `notifications`, `media`,
  `clipboard-sanitized-write`, `fullscreen`; deny everything else), spellchecker languages
  (`en-US` + `ar` if Chromium offers it), and a user agent equal to the real Chrome version of
  the bundled Electron (`process.versions.chrome`), never a hard-coded old one.

### 4.3 Guest hardening and behaviour (`guests/`)

- **harden.ts** (`will-attach-webview`): forces `contextIsolation`, `sandbox`, no node, the
  Diwan guest preload, and `src` = `https://web.whatsapp.com/`. Any other `src` is refused.
- **link-policy.ts** (pure): `classify(url)` returns one of:
  - `internal`: same origin as web.whatsapp.com, allowed to navigate;
  - `chat-link`: wa.me / api.whatsapp.com/send / `whatsapp:` → opened in the current account
    (`/send?phone=…&text=…`), never sends anything by itself;
  - `external`: other http(s) → `shell.openExternal` (default browser);
  - `blocked`: everything else (file:, javascript:, data: windows…).

  It is applied in `setWindowOpenHandler` (always `deny` + act), `will-navigate`, and the
  context menu. This fixes Nexus's raw Electron windows.
- **context-menu.ts**: spelling suggestions + Add to dictionary, Cut/Copy/Paste/Paste as plain
  text/Select all, Open link in browser, Copy link, Copy image, Save image as…, and
  Search the web for "…". Inspect is shown only in development.
- **downloads.ts**: saves to `~/Downloads` with a unique name and no dialog, then shows a
  notification ("Saved invoice.pdf"); clicking it reveals the file in the folder.
- **zoom.ts**: Ctrl+= / Ctrl+- / Ctrl+0 per account, stored in the account record.
- **watchdog.ts**: ported from Nexus. If a page is unresponsive for 10 s after Chromium flags it,
  the shell remounts that webview (never `forcefullyCrashRenderer`; that crashed Nexus).
- **shortcuts.ts**: `before-input-event` on the shell and every guest, mapped by a pure table:

  | Keys | Action |
  |---|---|
  | Ctrl+1…9 | account 1…9 |
  | Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+PgDn / PgUp | next / previous account |
  | Ctrl+R, F5 | reload account |
  | Ctrl+Shift+R | hard reload (remount) |
  | Ctrl+= / - / 0 | zoom account |
  | Ctrl+, | settings |
  | Ctrl+W | hide to tray |
  | Ctrl+Q | quit |

### 4.4 Guest preload (`preload/guest.ts`)

Runs in the isolated world of every WhatsApp page and only *reports*; it never clicks, types or
sends on its own, except to replay WhatsApp's own notification click handler.

- **Unread:** read by main from the guest's `page-title-updated` event, so no guest code is
  needed. It parses `(N)` with ASCII or Arabic-Indic digits (WhatsApp in Arabic shows `(٣)`),
  and the result does not depend on the UI language. Nexus's "unread" aria-label scraping did.
- **Notification bridge:** `contextBridge.exposeInMainWorld('__diwan', {notify, closed})`, plus a
  main-world shim (installed with `webFrame.executeJavaScript`) that replaces `window.Notification`
  with a class that:
  - forwards {title, body, tag, icon, silent} to main;
  - keeps WhatsApp's `onclick`;
  - reports `permission = 'granted'`.

  When the native notification is clicked, main tells the guest, and the shim calls the stored
  `onclick`. WhatsApp's own handler opens the right chat, in any language, with no selectors.
- **Connection state:** `online/offline` events + page ready → `state {loading|ready|offline}`.
- **Avatar (best effort):** first look 4 s after the page loads, then every 6 s, at most 10
  tries. The own picture is the one inside the left nav rail (new layout) or the top-left header
  (old layout), scored so that contact pictures lose. If found, it is sent as a data URL and main
  stores it as a 128 px file in `userData`. If not found, the rail shows initials. Account names
  are always set by the user, not scraped.

### 4.5 Notifications (`notify/`)

- Native `Notification` from main, title `"<Account> · <Contact>"`, body = message (or "New
  message" when `showPreview` is off), icon = contact image when WhatsApp provides one.
- Click → show + focus the window, switch to the account, replay `onclick` in that guest.
- Suppressed when the account is muted, notifications are disabled, or the window is focused on
  that same account (WhatsApp itself also suppresses those).
- Optional `markUrgent`: `win.flashFrame(true)`, which Hyprland/DMS shows as an urgent workspace.

### 4.6 Unread, tray, title (`unread/`)

- Totals from guest `unread` events; muted accounts don't count toward the badge (they still show
  their own number in the rail, in grey).
- Window title `Diwan` / `Diwan (5)`.
- Tray (StatusNotifierItem, which the DMS bar shows): the Diwan mark with a blue count badge. The
  badge PNGs (none, 1–9, 9+) are drawn once by the shell on a canvas and handed to main. Tray
  menu: Show, then one item per account (with its count), then Pause notifications (toggles `notifications.enabled`), then Quit.

### 4.7 Import from Nexus (`importer/`)

- **plan** (pure): reads `~/.newwhatsapp/config.json` and lists the live accounts (not the orphan
  partitions), with sizes and target ids.
- **apply:** refuses while Nexus is running (`SingletonLock` points at a live pid). Each partition
  is copied with copy-on-write (`fs.cp` + `COPYFILE_FICLONE`; instant on btrfs, normal copy
  otherwise) into `Partitions/acc-<newid>`, and the accounts are added to the store. Nexus's files
  are never modified or deleted.
- After the import, the dialog tells Joe to stop using Nexus. The same linked device session
  running in two apps can make WhatsApp log both out. It offers "Remove Nexus" instructions;
  Diwan does not uninstall anything itself.
- Offered on first run when `~/.newwhatsapp/config.json` exists, and later from Settings → Data.

### 4.8 Shell UI (renderer)

Graphite tokens, the same as Joe's other tools: background `#0f0f11 / #18181b / #1f1f23`,
lines `rgba(255,255,255,.07)`, text `#e4e4e7 / #a1a1aa / #71717a`, accent `#3b82f6`, danger
`#ef4444`. Fonts: Inter, plus JetBrains Mono for numbers and key caps. Radius 8–12 px. No glow
and no neon.

- **Account rail** (68 px, left):
  - the Diwan mark on top;
  - one 44 px tile per account: picture or initials on the account colour; the active tile has a
    3 px accent bar and a lighter tile; a blue unread pill (grey when muted); a small status dot
    for connecting/offline;
  - tooltip with the account name and shortcut;
  - drag to reorder; a "+" tile to add an account;
  - Settings at the bottom.
- **Context bar** (48 px, above WhatsApp; direction B, chosen 2026-10-22): the account colour
  dot, the name, the connection status and a "Muted" tag; on the right, zoom % (click to reset),
  mute toggle, reload, and "more", which opens the account menu.
- **Account menu** (right-click a tile): Rename, Colour, Picture…, Mute notifications, Reload,
  Reset zoom, Log out (clears the session), Remove….
- **Add account:** a small dialog (name + colour). The new account then opens on WhatsApp's QR page.
- **Status overlay** over a webview when offline/failed/hung: a card with a message, Retry, and
  Reload.
- **Settings** as a full panel (left section list): General, Notifications, Accounts, Data
  (import, open data folder), Shortcuts (read-only table), About (version).
- **No title bar by default.** On Hyprland the compositor draws the frame. The setting "Show
  window controls" adds a 32 px bar with min/max/close for floating window managers.
- Before any UI code: 2–3 visual mockups of the rail + settings for Joe to pick from, the same
  as was done for the polkit dialog.

## 5. Security

- Shell renderer: `contextIsolation`, `sandbox`, no node, strict CSP. It loads local files only.
- Guests: as in §4.3. Only web.whatsapp.com may load in a guest.
- IPC: every channel is typed and validated with zod. Shell channels accept only the shell's
  `webContents`, and guest channels accept only registered guests.
- The Chromium sandbox stays on. Nexus ran with `--no-sandbox`; Diwan does not.
- No telemetry and no network calls of its own. The only network traffic is WhatsApp's.

## 6. Error handling

| Failure | Behaviour |
|---|---|
| Config corrupt | load `.bak`; if that fails too → recovery mode (read-only, banner), never overwrite |
| Page fails to load / offline | overlay with Retry; reloads by itself when `online` fires |
| Page hung | watchdog → remount after 10 s |
| Guest renderer crash | remount, log it |
| Import while Nexus runs | refused, with a clear message |
| Notification shim missing (WhatsApp changed its code) | Chromium's own notification still appears (no account name), and a warning is logged once |
| Tray unavailable | the app still works; close-to-tray is disabled automatically |

Logs go to `~/.config/Diwan/logs/main.log` (rotated, 1 MB × 3). They never contain message text.

## 7. Testing

- **Unit (vitest):** store (atomic write, `.bak` recovery, recovery mode, migrate hook), schema
  defaults, link-policy (table of URLs), unread title parser (ASCII and Arabic digits, no
  count), shortcut table, importer plan (fixture configs incl. orphans), notification
  suppression rules.
- **E2E smoke (Playwright `_electron`):** launch with a temp `userData`, add an account, check
  that the webview reaches web.whatsapp.com and the rail shows the tile; open Settings; quit. It
  needs network, so it runs locally, not in CI.
- **Manual checklist on joe-cachyos** before calling 1.0 done: import both Nexus accounts with no
  QR; a notification from a background account opens the right chat; a link opens in Chrome;
  record and play a voice note; download a file; spellcheck suggests an Arabic correction; the
  tray count matches.
- CI (GitHub Actions): typecheck, lint, unit tests, and an Arch package build.

## 8. Packaging

- `appId` `com.yousef5.diwan`, productName `Diwan`, binary `diwan`.
- electron-builder → `dir` + AppImage. A `PKGBUILD` (`diwan`, built by `bun run package:arch`)
  installs to `/opt/diwan`, adds the `/usr/bin/diwan` launcher (no `--no-sandbox`; it passes
  `--ozone-platform=wayland` when `WAYLAND_DISPLAY` is set, because Electron 44 dropped
  `--ozone-platform-hint`), hicolor icons, and a `.desktop` file (`StartupWMClass=diwan`).
- The `.desktop` file has no `MimeType`, so installing Diwan never takes a default away from
  another app (Nexus still owns `whatsapp:` links). Diwan still handles them; Joe opts in with
  `xdg-mime default diwan.desktop x-scheme-handler/whatsapp`.
- Icon: a new Graphite mark (an arch / majlis doorway holding a speech bubble), designed with the
  mockups.
- Repo: `/mnt/joe-data/Coding/diwan`. Before anything is pushed to GitHub, Joe is asked first.

## 9. Open risks

1. **The notification shim depends on WhatsApp using `new Notification`.** If it moves to
   service-worker notifications, the click → chat feature degrades to "open the account".
   This is checked in the manual checklist and has the fallback in §6.
2. **Copied sessions:** it is assumed that WhatsApp's IndexedDB session works from a new partition
   path. This is verified with the smaller account first (108 MB), before the 1.7 GB one.
3. **Background throttling** of hidden webviews could delay notifications. This is measured with
   a test message to a background account. If needed, hidden guests get `backgroundThrottling: false`.
